## Design Context

### Users
MoeMail serves self-hosted operators and signed-in mailbox users. The domain management surface is restricted to administrators who need to add exact or wildcard domains quickly, understand what each rule enables, and avoid breaking active mail delivery.

### Brand Personality
Cute, calm, and practical. Administrative screens should retain MoeMail's friendly tone while prioritizing operational clarity, predictable controls, and explicit feedback over decoration.

### Aesthetic Direction
Stay within the existing Tailwind and Radix component language, including the current primary color, rounded panels, and light/dark themes. Use a compact responsive list inspired by the referenced Mail Platform domain page, but keep it visually consistent with MoeMail rather than recreating a separate console.

### Design Principles
- Make exact domains and wildcard domains visually distinguishable and explain their different effects.
- Keep common actions inline; use progressive disclosure for single and batch entry forms.
- Show the pending configuration before saving and provide precise validation and duplicate feedback.
- Preserve keyboard access, mobile usability, dark mode, and the existing MoeMail API contract.
- Treat configuration changes as deliberate operations: never hide unsaved state or imply that DNS is configured automatically.
